# ユーザーガイド

## はじめに

lab-resource-managerは、GPUサーバーや会議室といった研究室のリソースを、Google Calendarの予定として管理する予約システムです。

予約する方法は2つあります。Slackの`/reserve`コマンドでモーダルから作成するか、Google Calendarを直接開いて予定を作成するかです。どちらも同じ予約として扱われ、どちらか一方だけを使い続けても構いません。

全コマンドの一覧は、末尾の「コマンド一覧」にまとめています。

## 使い始める

初めて使うときは、次の2つの手順でリソースを予約できます。

### 1. メールアドレスを登録する

```text
/register-calendar <your-email@example.com>
```

このコマンドは、Slackユーザーと、予約の実体を管理しているGoogle Calendarのアカウントを紐付けます。
普段Google Calendarで使っているGoogleアカウントのメールアドレスを登録してください（Gmailのアドレスとは限りません。組織のGoogle Workspaceアカウントでも構いません）。

**登録すると:**

- Google Calendarのリソース（GPUサーバー、会議室など）への編集権限が自動的に付与されます
- 予約通知時にSlackでメンションされるようになります

まだ登録していない状態で`/reserve`を実行した場合は、予約モーダルより先に登録用のモーダルが開きます。このコマンドを先に打たずに`/reserve`から始めても構いません。

**例:**

```text
/register-calendar alice@example.com
```

### 2. リソースを予約する

```text
/reserve
```

このコマンドを実行すると、予約用のモーダルが開きます。

モーダルでは次を指定します。

- **リソースの種類**: GPUサーバーか会議室かを選びます
- **サーバー、または会議室**: 選んだ種類に応じて一覧から選びます
- **デバイス**（GPUサーバーを選んだ場合のみ）: 使用するデバイスをチェックボックスで選びます。1つも選ばなければ、そのサーバー全体を予約したものとして扱われます
- **開始・終了の日時**: 初期値は現在時刻から1時間後までです
- **備考**（任意）: 自由記述欄です

送信すると、予約が成立した場合は予約IDを含むメッセージが、他の予約と競合した場合は競合相手・リソース・時間帯を含むメッセージが、自分にだけ見える形で届きます。

どのデバイスが空いているかを先に確認したいときは、`/free`コマンドが使えます。「[いま空いているリソースを確認する](#いま空いているリソースを確認する)」を参照してください。そこにある「空いているものを予約」ボタンから開くモーダルも、このモーダルと同じものです。

**注意**: 開始時刻が終了時刻以降になっているなど入力に不備があると、エラーメッセージが表示されずモーダルだけが閉じ、予約が作成されないことがあります。送信後に予約が見当たらないときは、日時の指定を見直して再度実行してください。

## Google Calendarから直接予約する

Slackを使わず、Google Calendarを直接開いて予定を作成することでも予約できます。`/reserve`のモーダルも、内部では同じ形式の予定を作成しています。

### デバイス指定記法

GPUサーバーなどのリソースを予約する際、カレンダーのイベントタイトルで使用するデバイスを指定できます。

#### 基本的な指定方法

- **単一デバイス**: `0` → デバイス0
- **範囲指定**: `0-2` → デバイス0, 1, 2
- **複数指定**: `0,2,5` → デバイス0, 2, 5
- **混在指定**: `0-1,6-7` → デバイス0, 1, 6, 7

#### 予約例

Google Calendarイベントのタイトルにデバイス指定を記載します:

```text
0-2
```

この場合、デバイス0, 1, 2が使用されます。

```text
0,3,5
```

この場合、デバイス0, 3, 5が使用されます。

**注意**: タイトルにはデバイス指定のみを記載してください。説明文が必要な場合は、イベントの説明欄（description）に記載することを推奨します。

### 会議室の予約

会議室を予約する場合は、デバイス指定は不要です。通常通りGoogle Calendarにイベントを作成してください。

```text
研究室ミーティング
```

## いま空いているリソースを確認する

```text
/free
```

いま使えるリソースを一覧します。応答は自分にだけ見え、チャンネルには残りません。

### 表示の見方

```text
いま GPU 5台 が空いています

GPU             0  1  2  3
gpu-server-1    .  #  #  .
gpu-server-2    #  .  .  .

`.` 空き 　`#` 使用中

部屋
🔴 Meeting Room A — @tanaka 〜16:00

使用中のGPU
🔴 gpu-server-1 1,2 — @sato 〜18:00
🔴 gpu-server-2 0 — @tanaka 〜明日 09:00
```

表は列がデバイス番号に対応し、どの番号が空いているかを示します。
その下の一覧は、ふさがっているものについて予約者と終了時刻を伝えます。

すべてふさがっている場合は、最も早く空くリソースとその時刻を表示します。

### この先の空きを見る

応答の下にあるボタンから、日を切り替えられます。

```text
[ いま ] [ 今日 ] [ 明日 ] [ 他の日 ▾ ]
```

「他の日」では1週間先までを選べます。日付を打つ必要はありません。
選んだ日の表示は、リソースごとの空き時間帯になります。

```text
8月3日（月） 明日 の空き
✅ gpu-server-1 0 — 終日
✅ gpu-server-1 1 — 〜13:00, 17:00〜
この日は空きなし: gpu-server-1 2
```

`〜13:00` はその日の始まりから13時まで、`17:00〜` は17時からその日の終わりまでを意味します。
今日を見た場合は、過ぎた時間を除いた「いま以降」の空きが出ます。

### そのまま予約する

「空いているものを予約」ボタンを押すと、空きが最も多いサーバーとその空きデバイスを
選んだ状態で予約モーダルが開きます。選び直しも、そのままの送信もできます。

## 通知について

システムは定期的にGoogle Calendarのリソース使用状況を監視し、変更を検知すると設定されたSlackチャンネルに通知を送信します。

### 通知の内容

通知には以下の情報が含まれます:

- 使用者の名前（メールアドレスを登録している場合はSlackでメンション付き）
- リソース名（GPUサーバー名、会議室名など）
- 使用デバイス（GPUの場合）
- 使用期間

メールアドレスを `/register-calendar` コマンドで登録すると、自分の予約時に自動的にSlackでメンションされるため、
通知を見逃しにくくなります。

### 通知メッセージのボタン

予約の通知には、自分の予約を操作するためのボタンが付きます。

- **🔄 更新**: 予約の時間や備考を変更します
- **⏹️ 今で終了**: 進行中の予約をその時点で終了し、残りの時間を他の人に開放します。使った分は予約として記録に残ります
- **❌ キャンセル**: 予約そのものを取り消します。使った記録も残りません

予定より早く使い終わったときは「⏹️ 今で終了」を、そもそも使わなくなったときは「❌ キャンセル」を選んでください。
操作できるのは自分が所有する予約のみです。

## 使われていない予約のお知らせ

GPUの実利用監視が有効になっている場合、予約したGPUがしばらく使われていないと、Botから
ダイレクトメッセージが届きます。次の2つの場合があります。

- **あなたのプロセスが見当たらない**: 予約したGPUで、あなたのプロセスがひとつも動いていない
- **押さえたまま計算が走っていない**: プロセスは動いていて、GPUメモリも確保されているが、
  計算はしばらく走っていない（推論サーバーを立てたまま、ノートブックを開いたまま、
  学習ジョブが止まったまま、など）

後者のお知らせには、どのGPUのことなのか、確保しているメモリ量、その間の最大稼働率が
添えられます。心当たりと突き合わせて判断してください。プロセスがない場合より長く待ってから
届きます。

判定はGPU1台ずつ行われます。8枚予約して1枚だけ回している場合、残りの7枚についてお知らせが
届きます。残りを使い続けるならそのままで構いません。まとめて使い終わっているなら、いったん
終了して必要な枚数で取り直せます。

- **⏹️ 今で終了する**: その時点で予約を終了し、残りの時間を他の人に開放します（使った分は記録に残ります）
- **✅ まだ使う**: これから使う場合。しばらくこの予約については知らせません
- **❌ 予約を取り消す**: 予約そのものを取り消します

急かすためのものではなく、押さえたまま忘れていた予約に気づくためのものです。まだ使うなら
「✅ まだ使う」を押してそのまま続けてください。ただし黙るのは一定時間です。そのあとも
使われていなければ、改めてお知らせが届きます。

次の予約はお知らせの対象外です。

- 監視できていないサーバーの予約（レポートが届いていない場合、使われているかどうかを判断できません）
- `/link-user` でOSユーザー名が紐付いていない予約（あなたのプロセスをあなたのものと見分けられません）
- 会議室の予約
- まもなく終わる予約

## MCP経由でAIエージェントを使う（オプション）

MCP（Model Context Protocol）サーバーが有効になっている場合、Claude Codeのような
エージェントに、Slackを経由せず直接予約の閲覧・作成・更新・早期終了・キャンセルをさせることができます。

### アクセストークンの取得

```text
/mcp-token
```

事前に `/register-calendar` でメールアドレスが紐付けられている必要があります。トークンは
本人にしか見えないメッセージで表示されます。再実行すると新しいトークンが発行され、古い
トークンは即座に失効します。トークンを持っている人は自分になりすまして予約の作成・
キャンセルができてしまうため、他人に共有しないでください。

### MCPクライアントの設定

クライアントのMCP設定（例: `.mcp.json`）に、管理者から案内されたURLと`/mcp-token`で
取得したトークンを設定します:

```json
{
  "mcpServers": {
    "lab-resource-manager": {
      "url": "https://<lab-resource-managerのホスト>:8787/mcp",
      "headers": {
        "Authorization": "Bearer <取得したトークン>"
      }
    }
  }
}
```

正確なURL（ホスト名・ポート・`http://`か`https://`か）は管理者に確認してください。

### できること

- 今後の全予約の一覧表示、または自分の予約だけの一覧表示
- IDを指定して予約の詳細を取得
- 新しい予約の作成（GPUサーバーまたは会議室）
- 自分の予約の時間・備考の更新
- 進行中の自分の予約の早期終了（残り時間の解放）
- 自分の予約のキャンセル

早期終了は予約の終了時刻を現在時刻まで縮めるため、使った分は記録に残ります。予約そのものを
無かったことにしたい場合はキャンセルを使ってください。

更新・早期終了・キャンセルできるのは自分が所有する予約のみです（Slackの`/reserve`と同じ制約）。
